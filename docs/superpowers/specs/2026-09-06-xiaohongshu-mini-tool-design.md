# 「一卷山河」小红书小工具设计规格

日期：2026-09-06
状态：已获用户设计确认，待规格复核

## 1. 目标

在现有“五代十国互动历史探索”仓库内新增一个可独立构建、审计和上传的小红书离线小工具版本。它不是完整 Next.js 站点的静态镜像，而是面向移动端容器重新编排的轻量单页体验。

交付物包括：可上传 ZIP、1:1 PNG 图标、名称与简介、构建与审计脚本、校验摘要和合规评估。ZIP 根目录直接包含 `index.html`，总包目标小于 2 MiB，且不得超过 10 MiB。

## 2. 已选方案与取舍

采用独立纯静态小工具方案，在仓库中维护专用源码并复用现有历史数据。最终产物使用经典 `HTML/CSS/JS`，不依赖 Next.js 运行时。

未采用以下方案：

- 整站 Next.js 静态导出：现有多路由、API route、`fetch`、MapLibre Worker、外部地图资源和大体积 PMTiles 与容器规范冲突，改造范围和回归风险过大。
- 首页静态快照：实现简单，但缺少时间线、人物和事件探索，不能形成完整小工具价值。

## 3. 品牌与上架信息

- 名称：`一卷山河`（4 个汉字，低于 14 字限制）。
- 简介：`轻松逛懂五代十国`（9 个汉字，低于 14 字限制）。
- 图标方向：已确认 A1“山河入城”。奶油白圆角方形底，主体为青绿色立体纸雕城门与向前延展的河道，辅以一个朱砂红圆点。图形表达“进入历史”和“沿时间之河探索”，不使用小红书商标或第三方受保护图形。
- 图标交付：PNG、1:1、无文字、文件小于 5 MiB；生成后检查缩略图识别度、边缘、色彩和文件格式。

## 4. 产品范围

小工具采用单页内视图切换，不发生页面跳转：

1. 导览：解释 875—979 年内容范围，提供三条轻量阅读路径。
2. 时间线：按年份和主题筛选事件，默认只渲染当前结果，避免一次创建大量 DOM。
3. 人物：本地搜索和分类浏览，展示人物简介、所属政权、角色与关键生平事件。
4. 事件：展示背景、过程、结果、影响、相关人物和来源提示。
5. 山河：用简化 SVG 示意代表年份与政权更替，不加载瓦片、不使用 WebGL，不声称精确历史疆界。

不纳入小工具：在线聊天、服务端问史、API 路由、外部原文链接、剪贴板复制、地图瓦片、PMTiles、MapLibre、Worker、WebGL、用户账号、广告、付费、文件下载、外部跳转及小工具间跳转。

## 5. 技术结构

源码与生成物边界：

```text
mini-tool/
  src/
    index.html
    styles.css
    app.js
    data.js
    assets/
      icon.png
  README.md
scripts/
  build-mini-tool.mjs
output/xhs-mini-tool/
  一卷山河.zip
  icon.png
  validation-summary.md
```

`data.js` 由现有类型化 seed 数据生成，只保留小工具展示需要的字段，并挂载到受控的 `window` 命名空间。`app.js` 使用同一命名空间读取数据、管理当前视图、筛选条件和详情状态。脚本均为经典外链脚本，并按 `data.js` → `app.js` 顺序加载。

构建脚本只使用仓库已有 Node 运行时和标准库，完成清理目标目录、生成精简数据、复制静态文件、检查引用和打包。ZIP 仅包含允许的静态类型，不包含源码映射、配置、`node_modules` 或上层目录。

## 6. 兼容性与交互

- JavaScript 最终语法以 ES2017 / Chrome 61 为基线；不使用可选链、空值合并、对象 spread、模块语法或较新的运行时 API。
- CSS 先提供 Chrome 61 可用的布局、颜色和间距；不用 Flex `gap` 作为唯一实现，不依赖 `aspect-ratio`、`clamp()`、逻辑属性、`:has()`、Container Query 或动态视口单位。
- 使用 `viewport-fit=cover`，安全区采用容器变量与 `env()` 组合回退。
- 关键操作始终可见，不依赖 hover；按钮具有至少 44px 触控区域和可见焦点。
- 页面用 Pointer/Click 事件统一鼠标与触摸；滚动容器保留惯性滚动和长文本溢出处理。
- 所有核心内容在禁用动画或低性能设备上仍可使用。

## 7. 容器与服务协议合规

根据《小工具服务协议》和 `minitool-zip-builder` 1.6.0：

- 所有代码、数据和图片均随包提供；运行期不发起网络请求。
- 不调用定位、剪贴板、设备连接、传感器、实时通信、Worker、Service Worker、屏幕共享、全屏、凭据、外部窗口、动态执行代码或 WebAssembly。
- 不申请摄像头、麦克风、相册或其他敏感权限，不处理或向第三方传输个人信息，因此无需权限声明或隐私授权流程。
- 不嵌入 iframe、第三方广告、付费资源或站外内容。
- 历史内容继续保留“示意”“存在异说”和来源范围说明；不把 AI 演绎作为史料原文。
- 图标为本次原创生成素材；代码和现有素材在打包前检查许可与实际使用范围。
- 详情页清楚说明主要功能、适用范围、地图精度与必要提示。

协议合规评估属于基于当前协议文本和代码的工程审查，不替代平台最终审核或法律意见。

## 8. 状态与错误处理

- 初始视图为导览；切换视图只更新 DOM 和本地状态。
- 搜索或筛选无结果时显示可恢复空态，并提供清除筛选操作。
- 数据记录缺失关联实体时忽略无效关联并显示通用说明，不让页面白屏。
- SVG 山河示意不可用时回退为政权列表和年份说明。
- 运行环境不支持某个增强能力时保留基础布局，不按 UA 或设备型号分支。

## 9. 验证计划

1. 运行现有 typecheck、lint 和相关测试，确保数据复用未破坏主站。
2. 对生成目录和最终 ZIP 分别运行 skill 自带 Python 审计脚本；修复全部 `ERROR`，逐项判断 `WARN`。
3. 扫描禁用 API、外部 URL、内联脚本、行内事件、模块脚本、绝对资源路径、iframe/object 和不允许的文件类型。
4. 打开解压后的 `index.html`，在桌面和移动视口验证导航、筛选、人物/事件详情、年份切换、空态及键盘操作。
5. 检查 ZIP 根目录结构、文件清单、压缩前后大小、最大文本文件和 Base64 条目。
6. 检查图标为 1:1 PNG 且小于 5 MiB，并进行缩略图视觉复核。
7. 未获得小红书 PC 模拟器或真机运行数据时，在摘要中明确标注“Chrome 61 兼容性、真机性能和容器行为未实测”。

## 10. 完成标准

- 名称、简介和图标均可直接用于上传表单。
- ZIP 在根目录含唯一 `index.html`，仅含允许文件类型，自动审计无 `ERROR`。
- 核心功能完全离线，禁用能力扫描无业务代码命中。
- 历史内容、地图精度、来源及 AI 边界的提示清楚可见。
- 校验摘要列出通过项、警告、未实测项、协议风险和最终产物绝对路径。
