# 五代十国地图交互细节优化设计

## 目标

在不改变统一 MapLibre 架构和既有历史内容范围的前提下，解决四个影响阅读的问题：地图拖动、缩放时事件点跳动；多地点事件造成点位和引线拥挤；后周、北宋与北汉的旧版示意 Polygon 重叠；右侧政权列表拉长整页。

本轮只处理交互与示意数据表达。943 年正式重建快照不改动；下一批正式历史快照另行推进。

## 交互设计

### 连续投影

MapLibre 继续只创建一个实例。地图在 `move`、`zoom` 期间通过单个 `requestAnimationFrame` 节流发布投影更新，结束事件继续作为最终校正。每一帧最多触发一次 React 投影更新，避免事件点停在旧位置后突然跳到新位置。

系统启用“减少动态效果”时不增加装饰动画，但地图点仍需要准确跟随地理位置。

### 多地点事件聚合

采用已确认的 A 方案：同一历史事件关联超过 4 个地点时，不再把所有地点同时铺到低缩放地图上，而是在第一个有效的主要地点显示一个聚合印记，并标注覆盖地点数量。例如“燕云十六州归辽”显示为“16处”。

普通事件仍按地点聚合；同一地点发生多个事件时继续共用一个入口。默认状态取消长距离引线，只有发生小范围碰撞偏移时才使用短引线。弹窗保留完整事件标题和说明，不删除原始地点数据。

## 示意边界修正

951—960 年后周与北汉、960—979 年北宋与北汉是并存关系。当前旧版矩形/多边形只是示意，却在河东位置形成重叠，容易被理解为重复占领。

为后周和北宋使用带河东缺口的北方示意轮廓，北汉继续单独覆盖河东。缺口只用于消除视觉重叠，并保持 `illustrative`、低可信度和现有来源说明，不提升为正式疆域重建。北宋、后周标签下移，避免与北汉标签叠放。

## 页面布局

桌面端右侧政权栏设置与地图卡片协调的最大高度，政权列表和争议区在栏内独立纵向滚动。滚动条使用窄轨道、朱砂色滑块，并保持键盘、滚轮和触控板可用。

政权卡片纵向间距与内边距轻微收紧，信息字段不删减。移动端不建立内嵌滚动区，继续跟随页面自然滚动，避免双重滚动手势冲突。

## 数据流与错误处理

- `MapLibreCanvas` 负责节流地图运动事件并发布投影 revision。
- `MapEventMarkers` 负责事件地点聚合、碰撞定位和可访问按钮。
- `createIllustrativeAtlasDataset` 继续消费 seed 区域数据；河东缺口在 seed 示意轮廓中显式表达。
- 地形瓦片或辅助图层失败的既有降级逻辑保持不变。
- 事件没有有效坐标时继续跳过；聚合事件只有部分地点有效时，数量显示有效地点数。

## 验证范围

- 单元测试验证移动事件按帧合并、结束时最终校正。
- 单元测试验证超过 4 个有效地点的事件只生成一个聚合标记并保留地点数量。
- 数据测试验证后周、北宋示意轮廓不会覆盖北汉标签点。
- 组件测试验证桌面政权栏具有独立滚动语义，移动端仍自然流动。
- 运行现有单元测试、TypeScript、ESLint 和生产构建。
- 桌面与移动端各做一次浏览器冒烟，不新增大规模 E2E。

## 非目标

- 不修改 943 年正式快照。
- 不引入新的地图依赖或聚类库。
- 不在本轮制作 908、934、949、959 等正式疆域 Polygon。
- 不隐藏或删除历史事件、地点和来源数据。
