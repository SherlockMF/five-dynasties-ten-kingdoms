# 943 年历史疆域 GIS 数据集 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 产出一个可追溯、可校验、可由 QGIS 继续编辑的 943 年疆域数据集，并导出网站可直接加载的 GeoJSON。

**Architecture:** 以 `gis/943/wudai-943.gpkg` 为唯一人工编辑源，QGIS 工程只保存制图与配准配置。PowerShell 脚本调用本机 GDAL，把政权、争议区和地点分别导出为 EPSG:4326 GeoJSON；Vitest 与 `ogrinfo` 共同检查字段、几何、拓扑和来源完整性。

**Tech Stack:** QGIS 4.0.2、GDAL 3.12.4、GeoPackage、GeoJSON、PowerShell、TypeScript、Vitest。

## Global Constraints

- 首版年份固定为 943 年，所有面要素采用年末口径与半开有效区间。
- 研究范围固定为经度 72—136、纬度 18—55；发布坐标系固定为 EPSG:4326。
- `wudai-943.gpkg` 是唯一人工编辑源，导出的 GeoJSON 禁止手工修改。
- 水印地图只作交叉核对，不进入仓库、不裁切发布、不作为可分发底图。
- CHGIS 只在许可允许时进入发布产物；本计划首版仅把它记录为研究参考。
- 每个疆域必须记录 `sourceRefs`、`accuracyLevel`、`verificationStatus`；缺失时导出失败。
- 争议范围必须放入独立图层，不能伪装成确定控制区。

- [ ] **Step 1: 创建工程与数据层**

- [ ] **Step 4: 分离争议与推定边界**

史料不足或地图表达含糊的过渡带进入 `disputed_areas`，`boundaryKind` 固定为 `disputed`，`disputedNote` 必须解释争议对象。`realms` 中只有明确核心控制区可以使用 `accuracyLevel=attested`；依靠地图综合推断的边界使用 `reconstructed` 或 `approximate`。

- [ ] **Step 5: 添加地点与出处表**

`places` 至少包含开封、洛阳、幽州、金陵、杭州、福州、长沙、广州、成都、江陵；每个点包含现有站内 `locationId` 或稳定新 ID。`provenance` 每行对应一个 `sources.json` ID，并保存许可与说明。

- [ ] **Step 6: 执行 QGIS 拓扑检查**

```ts
import { readFileSync } from "node:fs";
import { resolve } from "node:path";
import { describe, expect, it } from "vitest";

const readJson = (name: string) =>
  JSON.parse(readFileSync(resolve(`public/maps/943/${name}`), "utf8"));

describe("943 atlas publication", () => {
  it("publishes all required realms with traceable metadata", () => {
    const realms = readJson("realms.geojson");
    const expected = [
      "later-jin", "liao", "southern-tang", "wuyue", "min",
      "chu", "southern-han", "later-shu", "jingnan",
    ];
    expect(realms.type).toBe("FeatureCollection");
    expect(new Set(realms.features.map((feature: any) => feature.properties.dynastyId)))
      .toEqual(new Set(expected));
    for (const feature of realms.features) {
      expect(feature.properties.validFromYear).toBe(943);
      expect(feature.properties.validToYearExclusive).toBe(944);
      expect(["controlled", "influence"]).toContain(feature.properties.boundaryKind);
      expect(["attested", "reconstructed", "approximate"])
        .toContain(feature.properties.accuracyLevel);
      expect(JSON.parse(feature.properties.sourceRefs).length).toBeGreaterThan(0);
    }
  });

  it("keeps every coordinate inside the declared East Asia extent", () => {
    const manifest = readJson("manifest.json");
    expect(manifest.bbox).toEqual([72, 18, 136, 55]);
    const realms = readJson("realms.geojson");
    const visit = (value: unknown): void => {
      if (!Array.isArray(value)) return;
      if (value.length === 2 && value.every((item) => typeof item === "number")) {
        const [longitude, latitude] = value as [number, number];
        expect(longitude).toBeGreaterThanOrEqual(72);
        expect(longitude).toBeLessThanOrEqual(136);
        expect(latitude).toBeGreaterThanOrEqual(18);
        expect(latitude).toBeLessThanOrEqual(55);
        return;
      }
      value.forEach(visit);
    };
    realms.features.forEach((feature: any) => visit(feature.geometry.coordinates));
  });
});
```

- [ ] **Step 3: 实现固定参数导出脚本**

`scripts/maps/export-943.ps1` 必须：解析仓库绝对路径；确认输入位于 `gis/943`、输出位于 `public/maps/943`；调用 `ogr2ogr` 时使用 `-t_srs EPSG:4326 -makevalid -lco RFC7946=YES -lco COORDINATE_PRECISION=5`；分别把 `realms`、`disputed_areas`、`places` 导出到对应文件；把 `gis/943/sources.json` 原样复制为发布目录的 `sources.json`；任何命令非零退出时立即停止。

核心调用固定为：

```powershell
& $ogr2ogr -f GeoJSON -t_srs EPSG:4326 -makevalid `
  -lco RFC7946=YES -lco COORDINATE_PRECISION=5 `
  $realmsOutput $packagePath realms
if ($LASTEXITCODE -ne 0) { throw 'Failed to export realms' }
```

其余两层使用同一参数，不改变字段名。
